# Экраны и состояния Today

## Принцип

В MVP это не набор независимых страниц, а состояния одной Today-поверхности. Такая модель сохраняет контекст и снижает стоимость повторного входа: пользователь всегда знает, где план, где написать об изменениях и где отметить результат.

## Карта состояний

| ID | Состояние | Триггер | Главный фокус | Приоритет |
|---|---|---|---|---|
| S-00 | Загрузка дня | Первый вход или смена пользователя в local MVP | Сохранить геометрию и объяснить ожидание | P0 |
| S-01 | Пустое утро | Нет задач и plan items | Выгрузить мысли | P0 |
| S-02 | Активный день | Есть scheduled tasks | Следующий выполнимый шаг | P0 |
| S-03 | Перегрузка | Есть `not_scheduled` | Отделить реальный план от хвостов | P0 |
| S-04 | Обновление дня | Отправлено сообщение | Сохранить контекст, затем объяснить изменения | P0 |
| S-05 | Все задачи закрыты | Все задачи дня имеют `done` | Дать ощущение завершения | P0 |
| S-06 | Вечерний итог | Пользователь явно подводит итог | Закрыть выполненное, сохранить хвосты | P1 UX / backend intent уже есть |
| S-07 | Ошибка и восстановление | Ошибка загрузки, сообщения или checkbox | Не потерять ввод и не соврать о статусе | P0 |
| S-08 | Завтра | Явный выбор будущего дня | Подготовить следующий день без смешения с сегодня | P1 |

## Общий каркас

```text
┌──────────────────────────────────┐
│ воскресенье, 2 августа           │
│ Сегодня                          │
│ Спокойно соберём день по шагам.  │
├──────────────────────────────────┤
│ Контекстная зона                 │
│ plan / empty / completion        │
├──────────────────────────────────┤
│ Свободный ввод                   │
│ большой утром, компактный днём   │
├──────────────────────────────────┤
│ Результат последнего изменения   │
├──────────────────────────────────┤
│ Не помещается / позже / цели     │
└──────────────────────────────────┘
```

На mobile используется один столбец и естественный scroll. На широком экране ширина основного контента ограничена, но структура не превращается в dashboard.

## S-00 — загрузка дня

**Задача пользователя:** понять, что приложение работает и не начало день с нуля.

**Композиция:**

- header показывается сразу;
- блок плана занимает стабильную ожидаемую высоту;
- 2–3 skeleton rows повторяют геометрию task row;
- composer видим, но submit disabled до завершения критичной загрузки;
- текст: «Собираю актуальный план…».

**Не делать:** spinner на пустой странице, прыжок всего layout после загрузки, технический статус backend в основном интерфейсе.

## S-01 — пустое утро

**Задача пользователя:** начать без предварительной настройки.

```text
Сегодня
Спокойно соберём день по шагам.

┌ План на сегодня пока пуст ───────┐
│ Напиши несколько мыслей —        │
│ я помогу собрать их в план.      │
└──────────────────────────────────┘

┌ Что у тебя в голове? ────────────┐
│ [ свободный многострочный текст ]│
│ Без формата и правильных слов    │
│                    [Собрать день]│
└──────────────────────────────────┘
```

**Правила:**

- brain dump — самый заметный интерактивный блок;
- empty state не выглядит ошибкой и не содержит обвиняющего «У вас нет задач»;
- профиль не блокирует начало; возможный default объясняется после построения плана;
- CTA активен только при непустом тексте;
- Enter создаёт перенос строки, отправка с клавиатуры — `Ctrl/Cmd + Enter`, если будет реализована.

**Критерий успеха:** пользователь без обучения понимает, что можно написать обычную фразу.

## S-02 — активный день

**Задача пользователя:** быстро понять, что делать и сколько уже сделано.

```text
План на сегодня             Сделано 2 из 4
Бережный темп               ━━━━━━━──────

┌ ☑ 09:00  Оплатить счета       20 мин ┐
└───────────────────────────────────────┘
┌ ☐ 11:00  Позвонить маме       15 мин ┐
└───────────────────────────────────────┘
┌ ☐ 17:00  Подготовить презентацию 60 м ┐
└───────────────────────────────────────┘

┌ Что изменилось? ─────────────────────┐
│ Добавь новую задачу или обстоятельство│
└───────────────────────────────────────┘
```

**Иерархия task row:**

1. checkbox;
2. название действия;
3. время старта;
4. оценка длительности;
5. pending/status feedback.

**Правила:**

- выполненные задачи не исчезают мгновенно: остаются спокойными в том же блоке, чтобы дать подтверждение и позволить отменить действие;
- progress считает все задачи выбранного дня, а не только scheduled items;
- время не показывается как точное обещание, если `start_time` отсутствует;
- при отсутствии времени и длительности используется «Без времени», но только один раз;
- порядок scheduled rows соответствует плану backend;
- компактный composer использует тот же `POST /api/message`.

**Критерий успеха:** следующий шаг читается без раскрытия карточки и без анализа всего списка.

## S-03 — перегрузка

**Задача пользователя:** увидеть предел дня без ощущения потери задач.

После scheduled tasks появляется отдельная секция:

```text
Не помещается сегодня                           2
Эти задачи сохранены, но план не обещает их выполнить.

○ Прочитать статью                         30 мин
○ Тренировка                                  1 ч
```

**Правила:**

- данные берутся из `plan.items[].status = not_scheduled`;
- секция не называется «Просрочено», «Не выполнено» или общим «Позже / без времени»;
- элементы не получают выдуманного времени;
- P0 не показывает controls переноса, потому что отдельного безопасного API переноса ещё нет;
- если список длиннее трёх элементов, в mobile он может быть свёрнут, но первый элемент и количество всегда видимы;
- AI-summary кратко объясняет причину, если backend имеет надёжные данные: «Две задачи не помещаются до сна».

**Критерий успеха:** пользователь различает «план» и «сохранённую задачу», не считая всё одной очередью обязательств.

## S-04 — обновление дня

### Во время отправки

- введённый текст остаётся в composer;
- CTA меняет подпись на «Собираю…» и становится disabled;
- существующий план остаётся видимым и интерактивно стабильным;
- отправляется только одно сообщение;
- никакого optimistic добавления распознанных задач до ответа backend.

### После успеха

Показывается одноразовый result card непосредственно после composer:

```text
План обновлён
Добавил две задачи и пересобрал вечер.
Обновлено: оплатить счета, 30 минут на проект
```

**Правила:**

- result card — не лента чата и не постоянная история;
- summary отвечает «что изменилось», а не повторяет весь план;
- изменённые task rows могут получить мягкую подсветку на 1.5–2 секунды;
- после перестроения scroll переносится к первому существенно изменённому блоку только если пользователь сам запустил действие и этот блок вне viewport;
- ARIA live сообщает краткий результат без повторного чтения всей страницы.

**Критерий успеха:** пользователь может проверить, правильно ли система поняла сообщение.

## S-05 — все задачи закрыты

**Задача пользователя:** завершить цикл без предложения «сделать ещё».

```text
┌──────────────────────────────────┐
│                 ✓                │
│ Все задачи закрыты               │
│ День закрыт мягко. Можно выдохнуть.│
└──────────────────────────────────┘

Выполнено 4 задачи · Бережный темп

[Подвести итог] — P1
```

**Правила:**

- все task rows остаются ниже в спокойном состоянии или сворачиваются в «Выполнено N» с возможностью раскрыть и отменить checkbox;
- no confetti, streak pressure и score;
- brain dump остаётся доступным, но визуально вторичен;
- новое дело можно добавить, но интерфейс его не провоцирует;
- декоративная иллюстрация необязательна и не входит в P0.

**Критерий успеха:** экран даёт завершение и сохраняет возможность исправить случайный checkbox.

## S-06 — вечерний итог

Backend уже понимает `daily_summary`, но отдельный сценарий Web требует dogfooding.

**Предлагаемый P1-поток:**

1. Пользователь нажимает «Подвести итог» или пишет итог в composer.
2. Появляется подготовленная подсказка, а не многошаговая форма: «Что получилось, а что оставить активным?»
3. Ответ отправляется через общий message pipeline.
4. Result card перечисляет только изменения: выполнено, осталось активным, план обновлён.

**Не делать:** рейтинг дня, обязательную рефлексию, форму с отдельными полями и ручное распределение каждого хвоста.

## S-07 — ошибка и восстановление

| Ошибка | Что сохраняем | Сообщение | Следующее действие |
|---|---|---|---|
| Загрузка дня | Последние уже показанные данные, если есть | «Не удалось обновить день.» | «Повторить» |
| Отправка текста | Полный draft | «Текст сохранён — попробуй ещё раз.» | Повторная отправка |
| Checkbox | Старый status | «Не удалось обновить задачу. Прежний статус сохранён.» | Повторить tap |
| Частичный успех | Серверный результат операции | «Изменение сохранено, но весь день не обновился.» | «Обновить день» |
| Backend недоступен | Draft и текущая страница | «Сервис временно недоступен.» | Повторить позже |

**Правила:**

- error banner размещается рядом с затронутой зоной; глобальный banner нужен только при общей ошибке;
- цвет не является единственным сигналом;
- внутренние status codes и stack traces не показываются;
- ошибочный запрос checkbox не меняет визуальный status optimistic;
- после восстановления ошибка исчезает, но пользовательский ввод не очищается до подтверждённого успеха.

## S-08 — завтра

Состояние не входит в текущий P0 Web UI, хотя backend поддерживает `date=tomorrow`.

**Предложение:** компактный day switch рядом с датой: «Сегодня / Завтра». При выборе завтра:

- заголовок меняется на «Завтра»;
- progress выполненного не доминирует;
- composer получает подсказку «Что важно учесть завтра?»;
- задачи сегодня и завтра никогда не смешиваются в одном plan list;
- возврат к Today — один tap.

До подтверждения dogfooding не добавлять календарную навигацию и произвольный date picker.

## Матрица отображения данных

| Ситуация | План | Composer | Secondary content |
|---|---|---|---|
| Нет задач | Empty invitation | Большой | Цели только при полезном контексте |
| Есть scheduled | Task rows + progress | Компактный | Позже и цели ниже |
| Есть `not_scheduled` | Scheduled отдельно | Компактный | «Не помещается сегодня» сразу после плана |
| Все done | Completion panel + доступ к done rows | Вторичный | Итог дня, затем цели |
| Loading | Skeleton | Disabled | Не прыгает |
| Error без данных | Empty error surface | Draft доступен, submit по состоянию backend | Dev details скрыты |
| Error с данными | Последние валидные данные | Draft сохранён | Inline recovery |

| Контекст | Основной текст | Дополнение |

| Empty | «План на сегодня пока пуст» | «Напиши несколько мыслей — я помогу собрать их в план.» |
| Brain dump | «Что у тебя в голове?» | «Напиши как есть — я соберу из этого реалистичный план.» |
| Compact input | «Что изменилось?» | «Добавь новую задачу или обстоятельство.» |
| Low energy | «Бережный темп» | Без оценки пользователя |
| Medium energy | «Обычный темп» |  |
| High energy | «Много энергии» | Не использовать «максимальная продуктивность» |
| Overload | «Не помещается сегодня» | «Задачи сохранены, но не входят в реалистичный план.» |

| Checkbox pending | «Обновляю…» | Checkbox disabled только у этой задачи |

## Доступность и клавиатура

- touch target каждого checkbox и button — минимум 44×44 px;
- видимый focus ring не удаляется;
- checkbox получает action-oriented accessible name: «Отметить задачу … выполненной» / «Вернуть задачу … в план»;
- progress имеет текстовый эквивалент `Сделано X из Y`;
- strike-through у done-задачи дублируется checkbox и подписью «Сделано»;
- ошибка объявляется через `role=alert`, успешное обновление — через ненавязчивый `aria-live=polite`;
- при `prefers-reduced-motion` подсветка и переходы отключаются;
- логический DOM-порядок совпадает с визуальным.
