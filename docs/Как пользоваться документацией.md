# Как пользоваться документацией

Папка `docs/` — единый Obsidian vault и канонический источник продуктового контекста AI Life Planner.

## Быстрый старт

1. В Obsidian выбери **Open folder as vault**.
2. Открой папку `docs` из корня репозитория.
3. Начинай работу с [[00 Главная]].
4. Перед выбором следующей задачи проверь [[02 Дорожная карта/Сейчас — далее — позже]] и [[03 Решения/Журнал решений]].

## Как устроена документация

- `01 Продукт` отвечает на вопрос, что и для кого мы строим.
- `02 Дорожная карта` фиксирует один текущий фокус и последовательность этапов.
- `03 Решения` хранит принятые продуктовые и архитектурные решения.
- `04 Дизайн` описывает утверждённое визуальное направление.
- `05 Тестирование продукта` собирает UAT, ежедневный dogfooding и UX-проблемы.
- `06 Идеи и бэклог` хранит отложенные возможности без размывания текущего спринта.
- `07 Техническая документация` содержит устойчивые инженерные ограничения.
- `99 Шаблоны` содержит общие шаблоны заметок.

## Ежедневное тестирование

Core plugin Daily notes настроен так:

- папка записей: `05 Тестирование продукта/Ежедневные записи`;
- формат имени: `YYYY-MM-DD`;
- шаблон: `99 Шаблоны/Ежедневное тестирование`.

Создавай одну запись на реальный день использования. Повторяющиеся проблемы переноси в [[05 Тестирование продукта/UX-проблемы]], а решения — в [[03 Решения/Журнал решений]].

## Правила изменений

- Не создавай вторую заметку с тем же назначением: обновляй каноническую.
- Пользовательские названия и основной текст веди по-русски.
- Команды, API endpoints, имена классов, функций и environment variables оставляй в исходном техническом виде.
- Изменение продуктовой стратегии, архитектуры или этапа roadmap должно обновлять соответствующую заметку в том же commit.
- Мелкая CSS-правка или исправление опечатки не требует механического обновления vault.
- Не коммить `workspace.json`, `workspace-mobile.json`, cache и персональные плагины Obsidian.
