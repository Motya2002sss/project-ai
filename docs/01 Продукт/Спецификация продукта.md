# Спецификация продукта

## Что такое AI Life Planner

AI Life Planner — адаптивный персональный планировщик, который превращает естественный язык в сохранённый профиль, долгосрочные цели, задачи с ограничениями, проверенное расписание дня и итоги.

Это не обычный todo-list и не command-only Telegram bot. Пользователь должен писать так, как думает: «Сегодня работаю до 19, сил мало, завтра хочу позаниматься математикой. Что сделать для целей?»

## Ценность для пользователя

Главная ценность — уменьшение ручной работы по планированию. Пользователь не должен поддерживать десятки полей, приоритетов, дат и переносов. Система запоминает устойчивый контекст, извлекает структуру из текста и помогает решить, что реалистично сегодня.

Parser или LLM извлекает предполагаемый смысл. Backend остаётся источником правды: валидирует данные, хранит состояние, меняет статусы и строит планы.

## Основные сценарии

### 1. Профиль

- Пользователь сообщает рабочее время и сон обычным языком.
- Система сохраняет начало и конец работы, время сна, имя и timezone.
- При неполном профиле планирование использует defaults и объясняет, какие данные улучшат результат.

### 2. Цели

- Пользователь добавляет любые долгосрочные цели.
- Цели хранятся как постоянные записи, а не только в chat history.
- Поддерживаются финансы, учёба, здоровье, семья, творчество, карьера и личные проекты.

### 3. Задачи

- Пользователь описывает дела свободным текстом.
- Parser извлекает operation, fixed/flexible semantics, priority, duration, date, preferred window и явные временные ограничения.
- `Task.target_date` разделяет сегодня и завтра.
- Create, update, cancel и complete разрешаются только внутри user context.
- Прошедший факт не превращается в новую задачу, а неоднозначная ссылка возвращает clarification.

### 4. Действия по целям

- По явному запросу система предлагает небольшие действия из активных целей.
- Действия добавляются на выбранный день.
- Текущие fallback-эвристики универсальны; LLM может повышать качество, но не выполняет запись в БД напрямую.

### 5. План дня

- Parser или LLM не строит окончательное расписание. Backend рассчитывает его детерминированно с шагом 15 минут.
- Availability учитывает текущий момент, рабочее время, buffer после работы, сон, fixed events, существующие интервалы, preferred window, earliest start и latest end.
- Fixed элементы не двигаются молча. Конфликт fixed intervals возвращает clarification без частичной мутации.
- Flexible элементы получают проверенный свободный слот; валидные существующие позиции сохраняются для minimal disruption.
- Overlap между scheduled plan items запрещён invariant-проверкой.
- Если корректного окна нет, задача остаётся `not_scheduled` с конкретной причиной. Это честный продуктовый результат, а не ошибка заполнения timeline.

### 6. Статус и итог дня

- Задачу можно перевести `planned → done` и вернуть `done → planned`.
- Status API фильтрует изменение по `task_id + user_id`.
- Итог дня закрывает выполненное, оставляет невыполненное активным и перестраивает план.
- Выполненный элемент сохраняет исходное время как история дня и не создаётся повторно из повторного сообщения.

### 7. Перепланирование

- Пользователь сообщает, что задержался или освободился позже.
- План перестраивается от нового доступного времени, перемещая только элементы, которые больше нельзя сохранить.
- Backend возвращает factual plan diff: created, updated, completed, cancelled, moved и unscheduled task IDs.

### 8. Web и будущий голосовой ввод

- Telegram text, Web text и будущий voice transcript используют общий `process_user_message()` pipeline.
- Voice должен сначала преобразоваться в текст, а затем пройти через тот же parser и services.
- Today Web UI показывает план, progress, задачи, goals и спокойный AI-summary.

## Что работает в MVP

- Telegram bot и FastAPI `/health`.
- PostgreSQL, SQLAlchemy и Alembic.
- Mock parser и опциональные OpenAI, OpenAI-compatible и native Ollama providers с fallback.
- Pydantic validation LLM output и parser eval dataset.
- Общий message processing service.
- Профиль, цели, задачи, `Task.target_date`, today/tomorrow separation.
- Goal task suggestions и work/sleep-aware planning.
- Adaptive interval scheduler, fixed/flexible/unscheduled tasks, conflict/clarification contract и factual plan diff.
- Mark done, reversible task status, daily summary и reschedule.
- Минимальный Vite/React Today Web UI.
- API чтения profile, goals, tasks и plans; `POST /api/message`; `PATCH /api/tasks/{task_id}/status`.
- User isolation в task status mutation.
- Smoke-check `scripts/check_mvp.py` и автоматические тесты.

## Что пока не готово

- Production authentication и защищённая идентификация Web-пользователя.
- Production deployment, observability и rate limits.
- Полный Web API и многоэкранный Web UI.
- Voice/STT и native mobile app.
- Production-выбор LLM provider на основе dogfooding и eval.
- История прогресса по целям и более глубокое адаптивное планирование.
- Полноценный recurring engine и многошаговый clarification dialogue.

## Ближайший продуктовый шаг

Начать ежедневный dogfooding Today screen, собирать реальные ошибки понимания и выбирать следующую функцию по повторяющейся боли, а не по размеру backlog.
