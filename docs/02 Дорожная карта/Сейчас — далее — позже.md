# Сейчас — далее — позже

## Сейчас — dogfooding adaptive Living Day

Living Day и Planning Engine v2 готовы к совместному dogfooding:

- [x] обратимый checkbox `planned ↔ done`;
- [x] user isolation при смене статуса;
- [x] API-тесты `done`, `planned`, 404, 422 и legacy `/done`;
- [x] разделение большого frontend-файла на `api.ts`, `types.ts` и небольшие компоненты;
- [x] loading, error, empty, mixed и all-done states;
- [x] актуализация README;
- [x] `scripts/check_mvp.py`, `pytest` и frontend production build;
- [x] Living Day / Intelligent Minimal вместо Soft Light;
- [x] безопасный `focus_text` из реальных plan items;
- [x] scheduled и unscheduled task rows без floating cards;
- [x] нижний composer с сохранением draft и честными success/error states;
- [x] локальный checkbox rollback и retry;
- [x] responsive-проверка 320–560 px и центрированный desktop canvas;
- [x] fixed, flexible и unscheduled semantics в parser и Task;
- [x] deterministic availability и поиск свободных слотов с шагом 15 минут;
- [x] запрет overlaps и clarification для fixed conflicts;
- [x] minimal disruption для валидных существующих интервалов;
- [x] user-scoped create/update/cancel/complete без смысловых дублей;
- [x] factual plan diff для Web и Telegram pipeline;
- [x] atomic DaySnapshot после message submit без GET waterfall;
- [x] persistent clarification/confirmation/conflict context с expiry и user isolation;
- [x] idempotency key и plan version для retry и stale proposal;
- [x] обязательный БЖУ clarification flow и честный unsupported capability;
- [x] ограниченные daily/weekdays/selected-weekdays routines;
- [x] постоянный рабочий график отделён от дневных availability overrides и не создаёт фиктивные задачи;
- [x] frontend message state machine, request timeout, stale-response guard и draft preservation;
- [ ] минимум три последовательных дня реального dogfooding.

### Один текущий фокус

Использовать Today screen в реальной жизни и проверять новый adaptive planner на реальных изменениях дня: fixed conflicts, переносах, задачах без времени и сохранении уже хорошего плана.

### Не сейчас

- native mobile app;
- voice;
- пользовательская интеграция с Obsidian;
- production auth;
- payments;
- сложный календарь;
- полноценный recurrence engine, исключения серий и calendar sync;
- отдельная бизнес-логика для voice;
- Kubernetes;
- бесконечная визуальная полировка.

## Далее — 3–7 дней ежедневного тестирования

- создавать запись через [[99 Шаблоны/Ежедневное тестирование]] каждый день;
- собирать реальные ошибки понимания;
- проверять реалистичность плана и корректность переносов;
- фиксировать повторяющиеся проблемы в [[05 Тестирование продукта/UX-проблемы]];
- выбрать одну следующую правку по частоте и влиянию на основной цикл.

## Позже — персональная бета

- простая production authentication;
- cloud deployment;
- production-safe logging и monitoring;
- usage analytics без сбора лишних персональных данных;
- несколько тестовых пользователей;
- выбор production LLM;
- расширение API и UI только под подтверждённые сценарии.
