# iOS Today P0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a live iOS-first Expo client that renders the authoritative backend Today snapshot, sends natural-language capture, handles every P0 interaction state, and completes tasks without moving planning logic onto the device.

**Architecture:** Expo Router owns navigation, while a root planner provider coordinates the typed `/api/v1` client, secure dogfood token, cache, draft, and reducer-driven request lifecycle. API DTOs are mapped into immutable Today presentation models; the UI never sorts, schedules, interprets text, calculates progress, or synthesizes conflicts. AsyncStorage holds only the latest snapshot and capture draft, while SecureStore holds the bearer token.

**Tech Stack:** Expo SDK 54, React Native, TypeScript, Expo Router, AsyncStorage, Expo SecureStore, Expo Haptics, Vitest, ESLint.

## Global Constraints

- Work only in `mobile/` except this implementation plan and the existing roadmap status after verified completion.
- Preserve the locked palette, hierarchy, timeline, navigation, capture behavior, and information density from Mobile Product & Design Handoff v1.
- Mobile is responsible only for capture, display, interaction, and doing; the backend remains the canonical source for understanding, planning, adaptation, conflicts, and goal progress.
- Never send `user_external_id`, never bundle a bearer token in source, and never expose Authorization values in logs.
- A server `DaySnapshot` atomically replaces local presentation state after every successful response.
- Minimum interactive target is 44×44 pt; support safe areas, Dynamic Type, VoiceOver, keyboard avoidance, and Reduce Motion.
- P0 excludes onboarding, Week, Voice/STT, full Path/Profile, general Undo, workout logging, push, integrations, and Android polish.
